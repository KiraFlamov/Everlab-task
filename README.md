# Crypto Price Tracker

Backend-сервис для отслеживания и агрегации цен криптовалют через [CoinMarketCap API](https://coinmarketcap.com/api/documentation/v1/).

- REST API с аутентификацией по Bearer-токену (API Key): полный ключ и необязательный read-only ключ.
- CRUD списка отслеживаемых криптовалют. Символ проверяется через CoinMarketCap.
- Актуальные цены из CoinMarketCap. Если CMC недоступен, отдаются последние сохранённые цены.
- История цен в SQLite (raw SQL, без ORM) с фильтрацией по датам и пагинацией.
- Фоновая синхронизация цен с корректной остановкой по SIGINT/SIGTERM.
- Таймауты, ретраи с экспоненциальным backoff и единый формат ошибок внешнего API.
- Swagger UI (`/docs`) и спецификация OpenAPI 3.0 (`/docs/openapi.json`).

## Стек

Node.js (20+), TypeScript, Express 5, SQLite (`better-sqlite3`), axios, swagger-ui-express, Jest + Supertest (+ ts-jest), Docker / docker-compose.

## Запуск

### Локально

Нужен Node.js 20.12 или новее.

```bash
npm ci
cp .env.example .env      # заполните API_KEY и CMC_API_KEY
npm run build
npm start
```

- API: `http://localhost:3000/api/v1`
- Swagger UI: `http://localhost:3000/docs`
- Health check: `http://localhost:3000/health`

Файл `.env` подхватывается встроенным `process.loadEnvFile` (Node 20.12+), поэтому `dotenv` не нужен. Переменные окружения можно задать и напрямую: уже заданные переменные имеют приоритет над `.env`.

### Docker

```bash
cp .env.example .env      # заполните API_KEY и CMC_API_KEY
docker compose up -d --build
```

База данных хранится в volume `db-data`. `docker compose stop` отправляет SIGTERM: приложение прерывает все текущие запросы к CMC (и фоновой задачи, и HTTP-обработчиков), дожидается активных HTTP-запросов и закрывает БД.

### Тесты

```bash
npm test                 # все тесты
npm run test:coverage    # с отчётом о покрытии
npm run typecheck        # проверка типов, включая тесты
```

Тесты не обращаются к настоящему CoinMarketCap. Клиент CMC проверяется против локального HTTP-сервера, поэтому таймауты, сетевые ошибки, 4xx/5xx, 429, ретраи и отмена — это реальное поведение axios, а не моки. Остальные тесты работают на SQLite в памяти.

## Конфигурация

| Переменная | По умолчанию | Описание |
|---|---|---|
| `API_KEY` | — (обязательна) | Ключ с полным доступом (Bearer token), минимум 16 символов |
| `API_KEY_READONLY` | — | Необязательный ключ только для GET-запросов |
| `CMC_API_KEY` | — (обязательна) | Ключ CoinMarketCap. Хранится только в окружении и никогда не отдаётся клиенту и не пишется в логи |
| `CMC_BASE_URL` | `https://pro-api.coinmarketcap.com` | Для sandbox: `https://sandbox-api.coinmarketcap.com` |
| `CMC_TIMEOUT_MS` | `10000` | Таймаут одного запроса к CMC |
| `CMC_MAX_RETRIES` | `2` | Число повторов при таймауте, сетевой ошибке, 429 и 5xx |
| `CMC_RETRY_BASE_DELAY_MS` | `500` | Базовая задержка backoff (500 → 1000 → 2000 мс…) |
| `PRICE_CURRENCY` | `USD` | Единая валюта цен для всего приложения |
| `PRICE_MAX_AGE_MS` | `60000` | Цены старше этого значения `GET /prices` обновляет из CMC |
| `SYNC_ENABLED` | `true` | Включает фоновую синхронизацию |
| `SYNC_INTERVAL_MS` | `300000` | Интервал фоновой синхронизации |
| `DB_PATH` | `./data/app.db` | Путь к файлу SQLite. Каталог `data/` в `.gitignore` |
| `PORT` | `3000` | HTTP-порт |
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` (JSON-логи) |

Конфигурация проверяется при старте. Если значение некорректно, процесс завершается с понятной ошибкой.

> **Лимиты CoinMarketCap.** Бесплатный план (Basic) даёт 10 000 кредитов в месяц. Один запрос котировок стоит 1 кредит на каждые 100 монет. При интервале 5 минут фоновая задача тратит около 8 600 кредитов в месяц. При интервале 60 секунд расход составит около 43 000, и бесплатного лимита не хватит.

## API

Все эндпоинты `/api/v1/*` требуют заголовок `Authorization: Bearer <API_KEY>`. Полная интерактивная документация доступна в Swagger UI по адресу `/docs`.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/health` | Проверка сервиса и БД (без авторизации) |
| `GET` | `/docs/` | Swagger UI (без авторизации; `/docs` перенаправляет сюда) |
| `GET` | `/docs/openapi.json` | Спецификация OpenAPI 3.0 (без авторизации) |
| `GET` | `/api/v1/cryptocurrencies?limit&offset` | Список отслеживаемых криптовалют с последней ценой |
| `POST` | `/api/v1/cryptocurrencies` | Добавить в отслеживаемые: `{ "symbol": "BTC", "name"?: "..." }` |
| `GET` | `/api/v1/cryptocurrencies/{id}` | Получить криптовалюту |
| `PATCH` | `/api/v1/cryptocurrencies/{id}` | Изменить отображаемое имя: `{ "name": "..." }` |
| `DELETE` | `/api/v1/cryptocurrencies/{id}` | Перестать отслеживать (история цен удаляется каскадно) |
| `GET` | `/api/v1/prices?symbols=BTC,ETH` | Актуальные цены всех или выбранных отслеживаемых криптовалют |
| `GET` | `/api/v1/cryptocurrencies/{id}/history?from&to&limit&offset&order` | История цен |

### Примеры

```bash
TOKEN="Authorization: Bearer $API_KEY"

# Добавить BTC. Имя и id в CoinMarketCap подтягиваются автоматически, начальная цена запрашивается сразу
curl -X POST localhost:3000/api/v1/cryptocurrencies -H "$TOKEN" -H 'Content-Type: application/json' -d '{"symbol":"btc"}'
# 201 {"data":{"id":1,"symbol":"BTC","name":"Bitcoin","cmcId":1,
#      "latestPrice":{"value":67123.45,"currency":"USD","fetchedAt":"..."},"createdAt":"...","updatedAt":"..."}}

# Актуальные цены
curl localhost:3000/api/v1/prices -H "$TOKEN"
# 200 {"currency":"USD","data":[{"id":1,"symbol":"BTC","name":"Bitcoin","price":67123.45,"fetchedAt":"...","stale":false}]}

# История за январь 2024, по возрастанию
curl "localhost:3000/api/v1/cryptocurrencies/1/history?from=2024-01-01&to=2024-01-31T23:59:59Z&order=asc" -H "$TOKEN"
# 200 {"cryptocurrency":{...},"currency":"USD","data":[{"price":...,"fetchedAt":"...","sourceUpdatedAt":"..."}],
#      "pagination":{"limit":100,"offset":0,"total":42}}
```

### Ошибки

Все ошибки возвращаются в одном формате:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Request validation failed",
             "details": [{ "field": "symbol", "message": "Must contain 1-20 latin letters or digits" }] } }
```

| Статус | Код | Когда |
|---|---|---|
| 400 | `VALIDATION_ERROR`, `INVALID_JSON` | Некорректные параметры, тело или JSON. Неизвестные поля тоже отклоняются |
| 401 | `UNAUTHORIZED` | Нет токена, токен неверный или заголовок имеет неверный формат |
| 403 | `FORBIDDEN` | Read-only ключ на изменяющем запросе |
| 404 | `NOT_FOUND` | Нет записи, маршрута или символ не отслеживается |
| 409 | `CONFLICT` | Криптовалюта уже отслеживается |
| 413 | `PAYLOAD_TOO_LARGE` | Тело больше 10 КБ |
| 422 | `UNKNOWN_SYMBOL` | CoinMarketCap не знает такой символ |
| 502 | `EXTERNAL_API_UNAUTHORIZED`, `EXTERNAL_API_BAD_REQUEST`, `EXTERNAL_API_INVALID_RESPONSE` | CMC отклонил ключ или запрос либо вернул неожиданный ответ |
| 503 | `EXTERNAL_API_TIMEOUT`, `EXTERNAL_API_NETWORK`, `EXTERNAL_API_RATE_LIMITED`, `EXTERNAL_API_UPSTREAM_ERROR` | CMC временно недоступен. Ответ содержит заголовок `Retry-After` |
| 500 | `INTERNAL_ERROR` | Непредвиденная ошибка. Детали только в логе |

## Как это устроено

```
src/
├── index.ts                 # точка входа: конфиг, БД, сервер, фоновая задача, сигналы
├── app.ts                   # сборка Express-приложения (все зависимости внедряются → тестируемость)
├── config.ts                # чтение и валидация переменных окружения
├── lifecycle.ts             # graceful shutdown + обработчики SIGINT/SIGTERM
├── clients/coinmarketcap.client.ts   # HTTP-клиент CMC: таймауты, ретраи, отмена, маппинг ошибок
├── db/database.ts           # подключение SQLite и миграции (PRAGMA user_version)
├── repositories/            # raw SQL
├── services/                # бизнес-логика (CRUD, синхронизация, «актуальные» цены)
├── jobs/price-sync.job.ts   # фоновая синхронизация
├── middleware/              # аутентификация, обработка ошибок
├── routes/                  # HTTP-слой
├── validation/validators.ts # валидация входных данных
└── docs/openapi.ts          # спецификация OpenAPI 3.0
```

### Модель данных

```sql
cryptocurrencies(id PK, symbol UNIQUE, name, cmc_id UNIQUE, created_at, updated_at)
price_history(id PK, cryptocurrency_id FK → cryptocurrencies ON DELETE CASCADE,
              price CHECK (price >= 0), currency, fetched_at, source_updated_at)
INDEX (cryptocurrency_id, currency, fetched_at)
```

- **`cmc_id`.** Символы в CoinMarketCap не уникальны: у нескольких монет может быть символ `BTC`. При добавлении символ разрешается через `/v1/cryptocurrency/map`. Выбирается активная монета с наивысшим рангом, и дальше котировки запрашиваются по однозначному `id`.
- **`updated_at`.** Обновляется при изменении записи и при каждом успешном получении цены.
- **`currency` в истории.** Валюта единая для приложения, но сохраняется в каждой записи. Если `PRICE_CURRENCY` когда-нибудь поменяют, старые записи в другой валюте не смешаются с новыми: все запросы фильтруют историю по текущей валюте.
- **Время.** Все даты хранятся в UTC в формате ISO 8601, поэтому сравниваются корректно как строки и используют индекс.

### Актуальные цены и недоступность CMC

`GET /api/v1/prices` берёт последние цены из БД. Цены старше `PRICE_MAX_AGE_MS` (или отсутствующие) сначала запрашиваются из CMC одним запросом и сохраняются в историю. Так данные остаются актуальными, а кредиты CMC не тратятся на каждый запрос. Состояние хранится только в БД.

Если CMC недоступен:

- есть сохранённые цены → `200`, цены помечены `stale: true`, в ответе есть поле `warning`;
- сохранённых цен нет → `503` или `502` с кодом причины.

### Фоновая задача

`PriceSyncJob` запускается сразу после старта сервера, затем повторяется каждые `SYNC_INTERVAL_MS`.

- Запуски выстраиваются цепочкой через `setTimeout`, а не `setInterval`, поэтому медленный CMC не приводит к параллельным синхронизациям.
- Ошибки внешнего API логируются со счётчиком подряд идущих неудач. Задача продолжает работать.
- `stop()` отменяет таймер, прерывает текущий HTTP-запрос через `AbortController`, включая ожидание backoff, и дожидается завершения итерации.
- Если криптовалюту удалили во время синхронизации, её цена не сохраняется.

Порядок остановки по SIGINT/SIGTERM:

1. Сервер перестаёт принимать новые соединения.
2. Отменяются запросы к CMC, которые ждут HTTP-обработчики (`GET /prices`, `POST /cryptocurrencies`). Без этого обработчик, застрявший в ретраях, держал бы остановку до ~31 с: 3 попытки по 10 с плюс паузы. После отмены `GET /prices` отдаёт сохранённые цены с пометкой `stale` (или `503`, если их нет), `POST` отвечает `503`.
3. Останавливается фоновая задача, её текущий запрос тоже отменяется.
4. Сервер дожидается завершения активных HTTP-запросов. Keep-alive соединения закрываются сразу после ответа, а не по keep-alive таймауту.
5. Закрывается БД, процесс завершается с кодом 0.

Если остановка не уложилась в 10 секунд, срабатывает принудительный выход с кодом 1. У docker-compose `stop_grace_period` 15 с, то есть больше этого запаса. Повторный сигнал не запускает остановку второй раз.

### Безопасность

- API-ключи сравниваются через `crypto.timingSafeEqual` по SHA-256-хэшам. Время сравнения не зависит от содержимого и длины ключа.
- Ключ CMC передаётся только в заголовке `X-CMC_PRO_API_KEY`. Исходные ошибки axios, в которых есть конфиг запроса с этим заголовком, не выходят за пределы клиента: они сразу превращаются в `ExternalApiError` с безопасным сообщением. Тесты проверяют, что ключ не попадает в ошибки.
- Все входные данные проверяются явно: тип и формат каждого поля, отсутствие неизвестных полей, отсутствие повторяющихся query-параметров, диапазоны чисел, корректность дат (например, `2024-02-31` отклоняется), лимит размера тела запроса.
- Все SQL-запросы параметризованы. Направление сортировки подставляется только из проверенного enum.
- Ответы на непредвиденные ошибки не содержат stack trace.

## Отступления от ТЗ и их обоснование

1. **Node.js 20+ вместо 18+.** Node 18 снят с поддержки (EOL — апрель 2025), и актуальные версии драйвера `better-sqlite3` (12.x) его не поддерживают. Последняя версия драйвера с поддержкой Node 18 (11.x) не имеет готовых сборок под актуальные версии Node, и её пришлось бы компилировать. Кроме того, `process.loadEnvFile` позволяет обойтись без `dotenv`, но появился только в Node 20.12. Docker-образ использует Node 24 LTS.
2. **Драйвер SQLite.** В стеке указан «SQLite (без ORM)», но для работы с SQLite из Node нужен драйвер. Выбран `better-sqlite3`: это тонкий синхронный драйвер для raw SQL без какой-либо ORM-логики. Встроенный `node:sqlite` потребовал бы Node 22.13+ и ещё не считается стабильным.
3. **Вспомогательные пакеты.** `swagger-ui-express` нужен для пункта «Swagger». `ts-jest` нужен, чтобы Jest запускал тесты на TypeScript. `@types/*` — только типы. Больше runtime-зависимостей нет: валидация, логирование, планировщик, загрузка `.env` и ретраи написаны на стандартных средствах Node.js.
4. **TypeScript 5.9, а не 7.** `ts-jest` пока не поддерживает TypeScript 7.

## Возможные улучшения

- Хранение API-ключей в БД (хэши, роли, отзыв ключей) вместо переменных окружения.
- Политика хранения (retention) или прореживание старой истории цен.
- Агрегаты по истории (min/max/avg/OHLC за период) — SQL-запросы поверх существующего индекса.
- Circuit breaker для CMC, чтобы не делать ретраи при длительной недоступности.
